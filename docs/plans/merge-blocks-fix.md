# Починка склеивания блоков (merge_block_up/down) — разбор и план

Источник: файл `pages/DHCP-сервер Kea высокой доступности.md` в графе
пользователя — после нескольких склеиваний JSON из разных код-блоков
перемешался, слово «Далее» разорвано посередине.

## Текущий алгоритм (`src-tauri/src/core/index.rs:451` `merge_block_up`)

1. Берётся предыдущий блок **в порядке документа** (`page.order[pos-1]`,
   без учёта видимости/уровня).
2. `content` текущего блока через пробел дописывается в `content`
   вышестоящего (`set_content`), trailing-строки текущего дописываются
   в конец trailing вышестоящего.
3. Дети текущего перепривязываются к вышестоящему, отступы поддерева
   переписываются через `strip_prefix(old_prefix)` с единицей отступа
   от первого ребёнка (иначе tab).
4. Текущий блок удаляется, страница перезаписывается целиком.

## Воспроизведённые дефекты (scratch-тесты, прогон 2026-10-14)

1. **Склейка в первую строку вместо последней.** У вышестоящего блока есть
   trailing (многострочный контент, код-фенс): текст текущего блока
   прыгает на первую строку вышестоящего — «через» код-блок:
   `- Блок с кодом` + trailing ``` ``` ... ``` ``` + `- Следующий блок`
   → `- Блок с кодом Следующий блок` и код остаётся ниже. Визуально текст
   встал ПЕРЕД кодом, хотя пользователь склеивал строку ПОСЛЕ него.
   В Logseq склейка происходит с последней видимой строкой блока.
2. **Принудительный пробел при склейке.** `format!("{} {}", prev, cur)`
   вставляет пробел, которого не было в тексте пользователя. Для строк
   кода/JSON это ломает содержимое: несколько склеек подряд собирают
   разные строки JSON в одну через пробелы (строка 80 файла:
   `"control-sockets": { "hooks-libraries": [ "loggers": [`).
   Logseq склеивает без вставки символов (курсор просто стирается).
3. **Переписывание отступов поддерева неустойчиво к смешанным отступам.**
   `strip_prefix(&old_prefix).unwrap_or("")`: если ребёнок имеет отступ
   в другом стиле (tab vs пробелы) или меньшей глубины, суффикс
   обнуляется → вся ветка схлопывается на один уровень.
4. **Цель склейки — просто предыдущий в `order`.** Склейка верхнеуровнего
   блока с глубоко вложенным последним потомком предыдущей ветки
   («Внук пробелы Хвост») — формально как Logseq, но в сочетании с п.1
   и п.2 даёт разрывы посередине слов и переносы текста в чужие ветки.

## Что починено (ветка fix/merge-blocks, коммит a61fd19)

Уточнённая пользователем семантика: склейка — НЕ конкатенация строк.
**Первая строка склеиваемого блока становится отдельной строкой сразу
после последней строки вышестоящего, с сохранением своего отступа**
(бullet убирается, строка становится trailing-строкой вышестоящего блока).

Реализовано в `merge_block_up`:
1. В конец `prev.raw.trailing` вставляется `Trailing::Raw` с текстом
   и исходным `indent_str` текущего блока; хвостовые Blank-разделители
   перед вставкой съедаются. Никаких вставленных пробелов и триммов.
2. Маркер склеиваемого блока (TODO и т.п.) становится текстом строки
   (`marker + " " + content`), не теряется.
3. Дети перепривязываются по уровням: `indent = prev.indent + delta`,
   `indent_str = prev.indent_str + "\t"×delta` (канонический tab).
4. Тесты: `src-tauri/tests/block_merge.rs` — 11 кейсов, включая
   код-фенс, Blank-разделитель, смешанные отступы; roundtrip цел.
