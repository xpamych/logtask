# Формат .md-файлов

Контракт совместимости: граф читается и Logseq, и Logtask. Всё, что Logtask
пишет, должно открываться в Logseq как родное, и наоборот.

## Структура графа (как сейчас в твоём графе Logseq)
```
<граф>/
  journals/2026_09_11.md     — страницы по дням, формат yyyy_MM_dd
  pages/                     — обычные страницы (453 файла)
  assets/                    — картинки и вложения
  logseq/config.edn          — читаем при импорте (см. ниже)
  .logtask/settings.json     — настройки Logtask (свои, Logseq не трогает)
```

## Базовый блок (outliner)
```md
- <MARKER> [#PRIORITY] текст задачи #теги [[Ссылка]]
  свойство:: значение
  :LOGBOOK:
  CLOCK: [2026-01-18 Sun 19:08:08]--[2026-01-19 Mon 17:35:18] =>  22:27:10
  :END:
```
- Маркеры-пули `- ` в начале строки, уровень вложенности — отступы (`tab` и
  `2+ пробелов` — оба поддерживаются, при записи новых блоков используется tab,
  как в Logseq).
- Свойства — строка, следующая за блоком, с отступом вглубь: `key:: value`
  (пример из твоего графа: `source-id:: ppdb-225`).
- Блок считается задачей, если у него есть маркер статуса, приоритет или
  `deadline`/`scheduled`.

## Статусы (бэклог, к выполнению, в работе, на проверке, выполнено, отменено)
Logtask хранит статус в маркере блока — ровно как Logseq, без отдельных
свойств-костылей. Соответствие:

| UI (рус.)      | Маркер в .md     | Семантика                          |
|----------------|------------------|------------------------------------|
| Бэклог         | `LATER`          | отложено, в очереди                 |
| К выполнению   | `TODO`           | принято в работу                    |
| В работе       | `DOING`          | активная задача                     |
| На проверке    | `REVIEW`         | ждёт ревью/подтверждения            |
| Выполнено      | `DONE`           | закрыто                             |
| Отменено       | `CANCELED`       | отменено                            |

Порядок, цвета, видимость колонок — настраиваются в `.logtask/settings.json`;
набор маркеров фиксирован (эти 6), меняются только label/цвет/порядок/
видимость. Существующие `TODO`/`DONE`/`LATER` из твоего графа подхватываются
автоматически. При чтении понимаются и альтернативные маркеры Logseq
(`NOW`/`BACKLOG`/`WAITING` и др. — мапятся на каноничные, см.
`Status::from_marker`).

## Матрица Эйзенхауэра
Срочность и важность — отдельные свойства блока (читаемы и в Logseq):

```md
- DOING [#A] Вебхук в Gitea для ppdb-site
  urgency:: high
  importance:: high
  deadline:: <2026-10-05>
```
- Уровни: `low` / `medium` / `high`. По умолчанию: нет уровня = `low`, а
  приоритет Logseq `[#A]` = важность `high`, `[#B]` = `medium`.
- Свойства можно редактировать и из UI: меню блока (`mod+enter`) меняет
  значение и пишет `urgency::`/`importance::` в файл.
- Квадранты считаются так (`Block::quadrant()`, urgency/importance —
  эффективные, т.е. с фолбэком на приоритет и автосрочность):
  - **I — сделать**: urgency=high, importance=high
  - **II — запланировать**: urgency≠high, importance=high
  - **III — делегировать/быстро**: urgency=high, importance≠high
  - **IV — выкинуть**: urgency≠high, importance≠high
- Автосрочность: `deadline` в пределах 3 дней (константа `URGENT_DAYS`,
  захардкожена в `model.rs`) форсирует urgency=high на уровне вычислений
  (значение в файле не переписывает); просроченный дедлайн тоже считается
  срочным.

## Ссылки и обратные ссылки
- Вики-ссылки: `[[Имя страницы]]`, алиасы `[[Имя|как показать]]`.
- Теги: `#тег`, `#[[тег со пробелами]]` — тег = страница-тег, участвует в
  обратных ссылках.
- Block refs `((uuid))` — парсинг и индексация есть (ссылки учитываются в
  индексе), рендер-превью текста — фаза 7, создание не планируется.
- Имя файла страницы: `pages/<title>.md`, кириллица и пробелы — как есть
  (у тебя в графе так: `pages/Gitea - Plemya-x - TODO.md`). Маппинг
  `/` → `___` (Logseq `:file/name-format :triple-lowbar`) пока **не
  поддерживается**: namespaced-страницы показываются как `Foo___Bar`.

## Импорт настроек Logseq (одноразово)
Из `logseq/config.edn` реально парсится только `:default-queries`
(`config_edn.rs`): твои группы «Сейчас / Работа / PPDB / Gitea / Остальные
дела» превращаются в saved-запросы кастомного списка задач (см. 03-ui) и
пишутся в `.logtask/queries.json`. Остальные ключи (`:journals-directory`,
`:favorites`, `:start-of-week` и пр.) не импортируются — план.

## Запись: правила безопасности
- При правке страница сериализуется и перезаписывается **целиком**;
  round-trip сериализация сохраняет нетронутое содержимое байт-в-байт,
  включая page-level свойства, преамбулу и пустые строки.
- Атомарная запись: `файл.tmp` + fsync + `rename` (fsync и родительской
  директории) — чтобы не плодить sync-conflict.
- Перед записью сверяем mtime файла с прочитанным: если он изменился
  извне (Syncthing/Logseq), запись отклоняется, чтобы не затереть чужие
  правки.
- Ничего не пишем в `logseq/` и не трогаем `.transit`/SQLite Logseq.
