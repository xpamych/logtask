# Дизайн: настраиваемая сортировка подборок задач

Дата: 2026-10-14. Статус: утверждено пользователем.

## Проблема

Подборки задач (`SavedQuery`, страница «Задачи» → режим «Подборки») выводят
задачи в произвольном порядке: фронтенд вызывает `tasks_by_filter` (только
фильтр, `commands.rs:559-571`), а готовая сортировка в ядре
(`Graph::query()`, `query.rs:75-105`) нигде в приложении не используется.
Поле `sort` в `SavedQuery` есть, но `QueryEditor` его не редактирует,
а формат не поддерживает направление.

## Требования

- В подборке можно настроить сортировку по полям: статус, приоритет `[#A-C]`,
  срочность, важность.
- Поля комбинируются в упорядоченную цепочку (первое — главное, остальные —
  tie-break).
- У каждого поля своё направление (по возрастанию / по убыванию).
- Задачи без значения поля (нет приоритета/свойства) — всегда в конце,
  независимо от направления.
- Старые файлы `.logtask/queries.json` с `sort: ["priority"]` должны
  продолжать читаться.

## Ядро (`src-tauri/src/core/query.rs`)

- Новый тип `SortRule { field: SortField, direction: SortDirection }`,
  `SortDirection { Asc, Desc }`; serde snake_case
  (`{"field":"priority","direction":"desc"}`).
- `SavedQuery.sort: Vec<SortRule>`. Custom `Deserialize`: принимает старый
  формат (строка `"priority"` → `Asc`) и новый (объект). Сериализация всегда
  в новый формат.
- Компаратор `Graph::query()`: идёт по цепочке правил; ключи как сейчас
  (`priority_key`, `level_key`, `Status::order()`); при `Desc` порядок
  инвертируется; `None` всегда в конце при любом направлении.
- Семантика ключей:
  - приоритет — по маркеру `[#A]`/`[#B]`/`[#C]`;
  - важность — по `effective_importance()` (явное свойство, иначе из приоритета);
  - срочность — по `effective_urgency()` (явное свойство, иначе из дедлайна);
  - статус — по каноничному `Status::order()`.
- `SortField::CreatedAt` остаётся no-op, в UI не показывается.

## IPC (`commands.rs`, `lib.rs`, `api.ts`)

- Новая команда `tasks_by_query(q: SavedQuery) -> Vec<TaskDto>` →
  `graph.query(&q)`. Если `tasks_by_filter` после этого нигде не используется —
  удалить; регистрация в `invoke_handler!` (`lib.rs`).
- `src/lib/api.ts`: обёртка `tasksByQuery(q: SavedQuery)`; тип
  `SavedQuery.sort: SortRule[]` (TS-зеркало serde-контракта).

## UI

- `QueryEditor.tsx`: блок «Сортировка» — список строк
  `[поле ▾][↑/↓][вверх][вниз][✕]` + кнопка «Добавить поле». Направление
  нового поля по умолчанию: `Desc` для приоритета/срочности/важности,
  `Asc` для статуса. Подписи: статус / приоритет / срочность / важность.
- `Queries.tsx`: запрос задач — `tasksByQuery(q)` вместо
  `tasksByFilter(q.filter)`; `filterSummary` дописывает
  «сортировка: приоритет ↓, статус ↑»; шаблоны подборок получают дефолт
  `sort: [{ field: "priority", direction: "desc" }]`.
- Стили — в `public/styles/global.css`, через CSS-переменные.

Канбан и матрица не меняются (их внутриколоночная сортировка зашита).

## Тесты

- Unit-тесты в `query.rs`: цепочка полей, направление, `None` в конце при обоих
  направлениях, десериализация старого формата `sort`, round-trip сериализации.
- Проверка фронтенда — `npm run typecheck`.

## Не входит в объём

- Сортировка в канбане/матрице.
- Парсинг `sort-by` из `:result-transform` при импорте из `config.edn`.
- Сортировка по `created_at` (поля нет в модели).
