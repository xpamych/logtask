# Дизайн: страница «Задачи» и переработка правой панели

Дата: 2026-10-02
Статус: утверждено пользователем (с правкой: правая панель сохраняется)

## Контекст

Сейчас Канбан / Матрица / Запросы живут вкладками в правой панели.
Пользователю неудобно: задачам тесно в узкой панели, а «Запросы»
непонятны («так и не понял, как ими пользоваться»).

## Решение

### 1. Страница «Задачи» в левой навигации

- Новый пункт «✓ Задачи» в секции «Навигация» сайдбара (между «Журналы»
  и «Все страницы»).
- Открывается в центральной области (как «Все страницы»), вся ширина центра.
- Сверху переключатель режимов: **Канбан | Матрица | Подборки**
  (segmented control). Выбранный режим сохраняется в localStorage.
- Компоненты `Kanban` и `Matrix` переезжают без функциональных изменений.

### 2. Правая панель сохраняется, вкладки задач уходят

Панель остаётся как **контекстная**: в следующих итерациях там появятся
оглавление текущего md-файла, вкладка с визуальным графом и другие
инструменты, зависящие от того, что открыто в центре.

- Resizer, кнопка сворачивания в топбаре, настройка «ширина панели задач»
  (переименовать в «ширина правой панели») — остаются.
- Вкладки Канбан/Матрица/Запросы и кнопка «← К ленте журнала» из панели
  удаляются (возврат к ленте — через пункт «Журналы» слева).
- Временно, до появления оглавления, панель показывает одну вкладку
  «Оглавление» с заглушкой «скоро: оглавление текущей страницы».

### 3. «Запросы» → «Подборки задач»

Переосмысление для понятности, без изменения модели данных
(`SavedQuery`/`TaskFilter`, `queries.json`, импорт из config.edn — как есть):

- Терминология: режим называется «Подборки», кнопка «＋ Новая подборка».
  Подборка = именованный фильтр, всегда показывающий актуальный список задач.
- Пустое состояние: одна фраза-объяснение + шаблоны одним кликом:
  «Сейчас в работе» (DOING+REVIEW, открытые), «Бэклог» (LATER, открытые),
  «Всё открытое» (все открытые).
- В заголовке каждой подборки — человекочитаемое описание фильтра:
  `12 · открытые · В работе, На проверке · страница начинается с "Проект"`.
  Видно назначение подборки, не открывая редактор.
- Редактор на человеческом языке:
  - «Со страницы» (было «Страница (точно)»),
  - «Название страницы начинается с…» (было «Префикс страницы»),
  - «Скрыть страницу» (было «Кроме страницы»);
  - добавляются недостающие поля фильтра: **теги** (через запятую) и
    **квадрант матрицы** (выпадающий список) — в `TaskFilter` они есть,
    в UI не выведены;
  - подписи статусов берутся из настроек графа (не хардкод).
- Кнопка импорта переименовывается в «⤓ Импорт из Logseq».

### 4. Технические изменения

- `src/App.tsx` — новый вид `"tasks"` в навигации; удаление табов задач
  из правой панели (панель и её инфраструктура остаются).
- `src/components/TasksPage.tsx` — новый компонент-обёртка: переключатель
  режимов, рендер `Kanban` / `Matrix` / `Queries`.
- `src/components/Sidebar.tsx` — пункт «Задачи» в навигации.
- `src/components/Queries.tsx` — шаблоны, summary-строка, пустое состояние,
  новые тексты.
- `src/components/QueryEditor.tsx` — человеческие подписи, поля тегов
  и квадранта, подписи статусов из настроек.
- `public/styles/global.css` — стили переключателя режимов, summary,
  шаблонов; чистка стилей удалённых вкладок.
- `docs/03-ui.md` — обновить описание в том же коммите.

## Что не входит (следующие итерации)

- Оглавление md-файла в правой панели (реальное, не заглушка).
- Вкладка с визуальным графом.

## Тестирование

- Rust не меняется — `cargo test --workspace` должен остаться зелёным.
- Фронт: `npm run typecheck`.
- Ручная проверка: `npm run app:dev` — страница задач, три режима,
  создание подборки из шаблона, summary-строка, панель с заглушкой.
