# Дизайн: видео- и аудио-вложения в блоках со встроенным плеером

Дата: 2026-10-10
Статус: утверждено пользователем (вариант: копирование в `assets/`,
прикрепление через drag-and-drop и Ctrl+V, отдача файлов своим
uri-scheme protocol `logtask-asset`)

## Контекст

Нужно прикреплять видео к блоку и проигрывать его встроенным плеером.
Формат Logseq это уже предусматривает: вставка ассета пишется как
`![[../assets/имя.mp4]]` (или markdown-вариант `![alt](../assets/x.mp4)`),
Logseq сам рендерит плеер. Контракт формата (`docs/02-format.md`) не
меняется: в md остаётся обычный текст, round-trip не затрагивается.

В проекте уже есть половина механики:

- `src-tauri/src/commands.rs` — `resolve_asset_path` резолвит пути вида
  `../assets/...` и `assets/...` относительно корня графа с защитой от
  выхода за его пределы (покрыто unit-тестами);
- `src/lib/text.ts` — `parseInline` распознаёт `![[../assets/x.png]]` и
  `![alt](path)` как сегмент `image`;
- картинки сейчас отдаются IPC-командой `asset_data_url` (base64) — для
  видео это не подходит (память, отсутствие перемотки).

## Решение

### 1. Отдача файлов: uri-scheme protocol `logtask-asset`

В `lib.rs` регистрируется protocol-handler
(`register_uri_scheme_protocol`), который:

- извлекает путь из URL (`logtask-asset://localhost/<urlencoded-путь>`);
- резолвит его существующим `resolve_asset_path` (защита от `../` и
  выхода за корень графа — как есть);
- отдаёт файл потоком с поддержкой заголовка `Range` (нужна для
  перемотки видео) и корректным `Content-Type` по расширению
  (mp4/webm/mov/mkv/avi, mp3/ogg/wav/m4a);
- если граф не открыт или файл не найден — 404.

Картинки продолжают ходить через `asset_data_url` (не трогаем); плееры
используют только новый протокол.

### 2. Прикрепление: IPC-команда `attach_asset`

Новая команда в `commands.rs` (+ регистрация в `lib.rs`, обёртка
`attachAsset` в `src/lib/api.ts`):

```
attach_asset(block_id: BlockId, source_path: string) -> Result<BlockDto, String>
```

Поведение:

1. Проверяет расширение источника против белого списка
   (видео: mp4/webm/mov/mkv/avi; аудио: mp3/ogg/wav/m4a) — остальное
   отклоняется с понятной ошибкой.
2. Копирует файл в `assets/` графа; если имя занято — суффикс `-1`,
   `-2`, … перед расширением.
3. Дописывает в конец текста блока `![[../assets/<имя>]]` (через пробел,
   если текст непустой).
4. Перезаписывает страницу стандартным атомарным путём с проверкой
   mtime (как остальные команды записи).
5. Возвращает обновлённый блок (DTO как у `update_block`).

### 3. Рендер плеера (фронтенд)

- `text.ts`: `parseInline` классифицирует сегменты `image` по расширению
  target — добавляются типы `video` и `audio` (синтаксис тот же).
- `BlockView`: сегменты `video`/`audio` рендерятся как
  `<video controls preload="metadata">` / `<audio controls>` с
  `src="logtask-asset://localhost/<encodeURIComponent(путь)>"`.
- Стили (max-width 100%, тёмная рамка/фон через CSS-переменные) —
  в `public/styles/global.css`.
- Пользовательский текст по-прежнему нигде не интерпретируется как HTML:
  src строится только из распарсенного пути ассета.

### 4. Ввод: drag-and-drop и Ctrl+V

В `BlockView`:

- **Режим просмотра**: drop файла на блок → `attach_asset`.
- **Режим редактирования (textarea)**: `onDrop` и `onPaste` — если в
  `DataTransfer`/`clipboardData.files` есть файлы с допустимым
  расширением, берётся путь первого, вызывается `attach_asset`, блок
  обновляется из ответа; стандартная вставка текста при этом не
  ломается (preventDefault только когда есть файл).
- Путь к файлу из `File` получаем через
  `@tauri-apps/api/core`/`webview.getCurrentWebview()`-механизм DnD
  Tauri 2 (`onDragDropEvent` на окне либо `File.path` — по факту
  реализации; предпочтительно `webviewWindow.onDragDropEvent`, который
  отдаёт реальные пути).
- Ошибки команды показываются строкой под блоком (как существующие
  ошибки редактирования).

### 5. Тесты и проверки

- Rust unit-тесты: `attach_asset` — копирование в `assets/`,
  дедупликация имён (`x.mp4` → `x-1.mp4`), дописывание вставки в блок,
  отказ на недопустимом расширении, ошибка при несуществующем источнике.
- Тест на маппинг `Content-Type`/Range в protocol-handler (если
  тестируемо без запуска окна — иначе покрыть резолв путей).
- Прогон: `cargo test --workspace`, `cargo fmt`, `cargo clippy`,
  `npm run typecheck`.
- Ручная проверка: mp4 в блоке журнала проигрывается с перемоткой;
  файл открывается в Logseq как родная вставка.

### 6. Явно вне скоупа

- Прикрепление прочих типов файлов (документы, архивы).
- Внешние видео по http(s)-ссылкам (YouTube и т.п.).
- Удаление файла из `assets/` при удалении вставки из блока
  (сборка мусора — отдельной задачей, если понадобится).
