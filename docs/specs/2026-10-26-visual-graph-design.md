# Требования и дизайн: визуальный граф связей

Дата: 2026-10-26
Статус: утверждено пользователем; добавлено обновление в реальном времени

## 1. Назначение

Визуальный граф помогает видеть связи между страницами Logseq-графа,
находить изолированные страницы и переходить между связанными материалами.
Глобальный граф даёт обзор всего хранилища, локальный — окружение открытой
страницы.

Весь объём этого документа обязателен. Деление на MVP и последующие этапы не
предполагается.

### Цели

- Показывать страницы, журналы, теги, виртуальные страницы и вложения как
  узлы с настраиваемой видимостью.
- Строить связи из существующего индекса Logtask, не создавая второго
  источника истины.
- Обеспечить навигацию, фильтрацию, цветовые группы, поиск пути и ручную
  компоновку.
- Сохранять интерактивность на графах до 10 000 узлов и 25 000 уникальных
  рёбер.

### Не входит в объём

- Отображение отдельных блоков как узлов и построение блокового графа.
- Создание, удаление или изменение `.md`-файлов перетаскиванием узлов.
- 3D-режим, автоматический анализ сообществ и плагинный API графа.
- Произвольная иерархия папок Obsidian: Logtask индексирует только `pages/`
  и `journals/`, поэтому вместо неё используются тип страницы, относительный
  путь и правила группировки по имени.

## 2. Ограничения и соответствие архитектуре Logtask

- `.md`-файлы остаются единственным источником истины. Визуальный граф —
  производное представление текущего `Graph` в памяти Rust.
- Для построения рёбер используются `Block.links`, `Graph.pages` и
  `Graph.backlinks`; обратный индекс не порождает дополнительных рёбер.
- Полная переиндексация ядра после `graph-changed` сохраняется. Требование
  инкрементального обновления относится к DTO и визуальной сцене: frontend
  обновляет только изменённые узлы и рёбра, не пересоздавая весь renderer и
  не сбрасывая координаты незатронутых узлов.
- Рендеринг — WebGL, вычисление force-layout — в Web Worker. Главный поток
  не должен ждать стабилизации физики.
- Пользовательский текст не вставляется через `innerHTML`. Подписи и меню
  рендерятся без интерпретации содержимого страниц как HTML.
- Настройки графа хранятся в `.logtask/settings.json`, в секции `graphView`.
  Координаты — в отдельном производном `.logtask/graph-layout.json`. Это
  удаляемый кэш, а не база данных и не источник данных: его потеря меняет
  только расположение узлов.
- Файл layout записывается атомарно через существующий механизм записи
  `.logtask`. Ничего не записывается в `logseq/`, `.transit` или SQLite
  Logseq.

## 3. Рассмотренные архитектурные варианты

### SVG/DOM

Отклонён: тысячи узлов, рёбер и подписей требуют слишком большого числа
DOM-элементов и не обеспечивают заданные бюджеты панорамирования и зума.

### Canvas 2D и Web Worker

Подходит для небольшого графа, но возлагает всю растеризацию на CPU и требует
отдельных оптимизаций текста и видимой области. Не выбран, поскольку бюджет
10 000 узлов обязателен уже в первой версии.

### WebGL и Web Worker — выбранный вариант

WebGL выполняет пакетный рендер узлов, рёбер, стрелок и подписей; Worker
рассчитывает физику. Hit-testing выполняется по координатам без DOM-элементов
на каждый узел. WASM допускается для ускорения layout, но не обязателен:
выбор TypeScript или WASM определяется замерами и не меняет внешний контракт.
Конкретная библиотека не фиксируется этим документом.

## 4. Точки входа и режимы

### 4.1. Глобальный граф

- В раздел «Навигация» левого сайдбара добавляется пункт **«Граф»** — после
  «Все страницы» и перед «Настройки».
- Пункт открывает граф в центральной области, как журнал, задачи и страницы.
  Вид включается в существующую историю «назад/вперёд».
- Левый сайдбар остаётся доступен. Правая панель содержит вкладку
  **«Настройки графа»** с фильтрами, группами, отображением и физикой.
- Повторный вход использует сохранённые координаты, зум и позицию камеры;
  полный force-layout с нуля не запускается.

### 4.2. Локальный граф

- Для открытой страницы или журнала в контекстной правой панели добавляется
  вкладка **«Связи»**.
- В центре локального графа находится активная страница. Показываются узлы,
  достижимые не более чем за 1, 2 или 3 перехода; глубина выбирается в панели
  и сохраняется.
- Соседство для глубины считается без учёта направления ссылки, направленные
  рёбра сохраняют исходное направление.
- Локальный граф использует общие фильтры, цветовые группы, настройки
  отображения и физики глобального графа; отдельного набора этих настроек у
  него нет. Центральная страница показывается всегда, даже если исключена
  общим фильтром. Остальные узлы проходят действующие фильтры.
- Агрегация в локальном графе не применяется: максимальная глубина 3 уже
  ограничивает сцену. Все страницы окружения, прошедшие фильтры, показываются
  как обычные узлы.
- Клик по узлу локального графа делает страницу активной и перестраивает её
  окружение. Кнопка «Открыть в глобальном графе» переключает центральную
  область на глобальный граф, выбирает эту страницу и центрирует камеру на ней.
- Layout локального графа хранится отдельно для каждой центральной страницы,
  чтобы координаты разных окружений не перезаписывали друг друга.

## 5. Узлы

### 5.1. Типы и видимость по умолчанию

| Тип | Источник | По умолчанию |
|---|---|---|
| Обычная страница | `PageKind::Page` | показывать |
| Журнал | `PageKind::Journal` | скрывать |
| Виртуальная страница | цель `[[...]]` без `Page` | скрывать |
| Тег | `LinkTarget::Tag` | скрывать как отдельный тип |
| Вложение | ссылка на файл `assets/` из блока | скрывать |

Опция **«Показывать журналы»** независима от остальных фильтров. При выключенной
опции журналы и инцидентные им рёбра отсутствуют в сцене.

Тег и одноимённая страница образуют один узел, а не два. Если существует
страница тега, используется её идентификатор; включение узлов тегов добавляет
только теги без существующих страниц и меняет визуальный маркер узла. Опция
**«Только существующие страницы»** скрывает виртуальные страницы и теги без
файла.

Узел вложения соответствует файлу внутри `assets/`; страница, содержащая
ссылку на вложение, соединяется с ним ребром. Файлы без ссылок не создают узлы.
Распознаются только локальные ссылки Logseq/Markdown на `assets/`:

- `![[../assets/имя]]`;
- `![alt](../assets/имя)` и `![alt](assets/имя)`;
- `[текст](../assets/имя)` и `[текст](assets/имя)`.

Абсолютные пути, URL и пути с выходом за пределы `assets/` узлов не создают.
Для единого источника ссылок в проекцию в `LinkTarget` добавляется вариант
`Asset`; это расширение чтения не меняет сериализацию и не должно нарушать
round-trip исходного markdown.

### 5.2. Идентификация

- Страница идентифицируется стабильным ключом вида `page:<имя>`, журнал —
  `journal:<имя>`, вложение — `asset:<нормализованный относительный путь>`.
- Имя страницы — каноническое имя из `Graph.pages`, включая кириллицу и
  пробелы. Поддержка namespaced-страниц не добавляется: `Foo___Bar` остаётся
  именем `Foo___Bar`.
- Идентификатор не зависит от позиции блока и позволяет сохранить координаты
  после полной переиндексации.

### 5.3. Размер узла

Размер определяется числом уникальных соседей среди видимых узлов с учётом
входящих и исходных рёбер. Повторные ссылки между одной парой узлов не
увеличивают степень повторно.

Используется ограниченная нелинейная шкала: базовый радиус плюс коэффициент,
пропорциональный квадратному корню степени. Минимальный и максимальный радиус
ограничены, чтобы крупные узлы не перекрывали весь граф. Пользовательский
коэффициент размера умножается на результат.

## 6. Рёбра

- Ссылка из блока страницы A на страницу B создаёт направленное ребро A → B.
  Сама обратная ссылка B ← A вторым ребром не является.
- Если B также ссылается на A, в модели существуют два противоположно
  направленных ребра, но на сцене между этой парой узлов рисуется только одна
  линия со стрелками на обоих концах. Дублирующих линий нет ни для встречных,
  ни для повторных ссылок.
- Несколько ссылок A → B объединяются в одно ребро с весом, равным числу
  ссылок. Вес не меняет расчёт степени узла.
- Ссылка страницы на саму себя отображается как петля и не делает страницу
  несвязанной, но не добавляет уникального соседа.
- Теги образуют рёбра от страницы, в блоке которой они встречаются, к узлу
  тега. Если тег совпадает с обычной страницей, используется общий узел.
- `LinkTarget::Block` не создаёт ребро между страницами автоматически:
  блоковые ссылки относятся к блоковому графу и находятся вне этого объёма.
- После фильтрации остаются только рёбра, оба конца которых видимы.

## 7. Выбор, подсветка и кратчайший путь

### 7.1. Hover

При наведении узел, его непосредственные соседи и соединяющие рёбра
подсвечиваются; остальные элементы визуально приглушаются. Подпись узла
показывается независимо от порога подписей. Hover не изменяет сделанный
кликом выбор.

### 7.2. Выбор кликом

- Первый клик по обычному узлу выбирает его и подсвечивает непосредственных
  соседей и соединяющие рёбра.
- Клик по второму обычному узлу запускает поиск кратчайшего пути между ним и
  первым. Если путь найден, подсвечиваются только узлы и рёбра пути; его длина
  в переходах показывается в панели. Если пути нет, оба узла остаются выбраны,
  а панель сообщает «Путь не найден».
- Путь ищется BFS по видимому после фильтров графу без учёта направления и
  веса рёбер. При нескольких одинаково коротких путях выбирается
  детерминированный — лексикографическая сортировка соседей по стабильному
  идентификатору.
- Агрегация не меняет результат BFS: путь считается по исходным узлам до
  сворачивания кластеров. Если путь проходит через скрытые в кластере страницы,
  на сцене подсвечивается сам кластер и агрегированные рёбра соответствующего
  участка. Кластер не может быть начальной или конечной точкой пути.
- Клик по кластеру только раскрывает или сворачивает его и не меняет текущий
  выбор. Контекстное меню кластера содержит только «Развернуть»/«Свернуть»;
  действия со страницами становятся доступны после раскрытия.
- После показа пути клик по новому обычному узлу начинает новый выбор с него.
- Повторный клик по единственному выбранному узлу, клик по пустому фону или
  `Escape` сбрасывает выбор и подсветку.
- Двойной клик по странице открывает её в центральной области. Для локального
  графа действует правило смены активной страницы из раздела 4.2.

## 8. Фильтры

Панель глобального графа содержит следующие обязательные элементы:

- **Поиск** — регистронезависимое совпадение с названием страницы, тегами
  страницы и относительным путём файла. Несколько слов через пробел
  объединяются условием «И». Поиск фильтрует узлы, а не только подсвечивает их.
- **Показывать журналы**.
- **Показывать теги**.
- **Показывать вложения**.
- **Только существующие страницы**.
- **Скрыть страницы без связей** — скрывает узлы с нулём входящих и исходных
  рёбер после применения остальных фильтров. По умолчанию выключено, чтобы
  исходное состояние показывало все обычные страницы, включая изолированные.
- **Исключения** — список glob-паттернов для имени страницы или относительного
  пути, например `2026_*`, `pages/Черновик*`. Готовый переключатель журналов
  не заменяется паттернами.

Фильтры применяются к существующему снимку без повторного чтения `.md` и без
перезапуска layout для сохранившихся узлов. Скрытые узлы и рёбра удаляются из
сцены; при возвращении узла восстанавливается его последняя сохранённая или
детерминированная позиция.

Состояние фильтров сохраняется между перезапусками. В панели есть кнопка
**«Сбросить фильтры»**, возвращающая значения по умолчанию.

## 9. Цветовые группы

- Пользователь создаёт упорядоченный список правил **«условие → цвет»**.
- Условие использует тот же поисковый язык, что фильтр, и дополнительно
  поддерживает префиксы `tag:`, `name:`, `path:` и `kind:page` /
  `kind:journal`. Пример: `tag:active`, `name:Проект`, `kind:journal`.
- Первое подошедшее правило определяет цвет узла. Узел без совпадений
  использует цвет своего типа из темы.
- Цвета вложений, виртуальных страниц, тегов, журналов и обычных страниц
  различимы по умолчанию в обеих темах. Выбранный пользователем цвет не
  заменяет другие признаки типа: форма маркера или значок остаётся.
- Правила можно добавлять, редактировать, удалять, временно отключать и
  менять местами. Порядок и настройки сохраняются.
- Группа может использоваться для агрегации: переключатель правила
  **«Сворачивать в кластер»** объединяет подходящие узлы (раздел 13.4).

## 10. Внешний вид и физика

Обязательные настройки:

- стрелки направления на рёбрах;
- глобальный коэффициент размера узлов;
- глобальный коэффициент толщины рёбер;
- порог появления подписей в зависимости от зума;
- сила центрирования;
- сила отталкивания;
- сила притяжения по связям;
- желаемая длина связи;
- скорость стабилизации/затухания симуляции.

Изменение настроек применяется к открытой сцене без перезапуска приложения.
Изменение размера и толщины не пересчитывает координаты. Изменение физики
продолжает симуляцию из текущих позиций, а не сбрасывает layout.

При мелком зуме подписи, стрелки и декоративные эффекты упрощаются или
скрываются. Подписи выбранных, наведённых и входящих в путь узлов имеют
приоритет независимо от порога.

Кнопки **«Пересчитать раскладку»** и **«Сбросить настройки отображения»**
выполняются только после подтверждения, если затрагивают вручную
зафиксированные узлы.

## 11. Взаимодействие

- Колесо мыши и жесты изменяют зум относительно положения курсора.
- Перетаскивание фона панорамирует граф.
- Перетаскивание узла перемещает его; после завершения узел считается
  зафиксированным. В контекстном меню доступно **«Отпустить узел»**.
- Контекстное меню страницы содержит: **«Открыть страницу»**,
  **«Скопировать [[ссылку]]»**, **«Показать локальный граф»**,
  **«Зафиксировать/отпустить узел»**, **«Скрыть узел»**.
- «Скрыть узел» добавляет точное имя в сохраняемый список исключений; отмена
  выполняется в панели фильтров.
- Для вложения доступны **«Открыть файл»**, **«Показать в файловом менеджере»**
  и **«Скрыть узел»**.
- Камера поддерживает кнопки **«Вписать граф»**, **«Приблизить»**,
  **«Отдалить»** и **«Вернуться к выбранному»**.
- Зум, позиция камеры, координаты и фиксация узлов, глубина локального графа,
  фильтры, группы и настройки отображения сохраняются между перезапусками.

## 12. Доступность и локализация

- Все подписи, настройки, меню и сообщения — на русском, как остальной UI.
- Canvas получает клавиатурный фокус и доступное имя. Стрелки панорамируют,
  `+`/`-` меняют зум, `Escape` сбрасывает выбор.
- Видимые узлы доступны через клавиатурную навигацию с roving focus:
  `Tab`/`Shift+Tab` переключают узлы, `Enter` выполняет выбор, а доступное имя
  содержит название, тип и число связей. Для этого не создаётся DOM-элемент
  на каждый узел.
- Поиск узла доступен с клавиатуры; фокус не должен попадать в скрытые узлы.
- Цвет не является единственным носителем состояния: выбор, путь и тип узла
  имеют дополнительные визуальные признаки.
- Контраст подписей, фокуса и состояний соответствует текущей светлой и тёмной
  темам; настройка `prefers-reduced-motion` отключает необязательные анимации
  камеры и подсветки.

## 13. Производительность и масштабирование

### 13.1. Условия измерения

Проверка выполняется на release-сборке без открытых инструментов
разработчика. Используются воспроизводимые синтетические графы на 1 000,
3 000, 5 000 и 10 000 узлов; конфигурация тестовой машины и версия приложения
фиксируются рядом с результатами. Под интерактивностью понимается возможность
зумировать, панорамировать и выбрать узел с видимым откликом.

### 13.2. Время до интерактивности

- До 1 000 узлов: не более **2 секунд** от выбора пункта «Граф» до
  интерактивной сцены.
- Более 5 000 узлов: первый видимый каркас менее чем за **1 секунду**;
  стабилизация layout продолжается в фоне без блокировки UI.
- Повторное открытие с действительным кэшем layout: не более **300 мс** до
  полностью отрисованной сцены на 1 000 узлов.
- При первом открытии сразу используются детерминированные стартовые
  координаты; ожидание «успокоения» физики не требуется.

### 13.3. Плавность и простой

- На 3 000 видимых узлах и 7 500 рёбрах панорамирование и зум обеспечивают
  **не менее 30 FPS для 95% кадров**, целевое значение — 60 FPS.
- Ни одно действие пользователя не блокирует главный поток дольше 100 мс;
  на графе 10 000 узлов / 25 000 рёбер отклик интерфейса не блокируется
  дольше 1–2 секунд даже при автоматическом упрощении сцены.
- После стабилизации физики Worker останавливает расчёт тиков, renderer —
  постоянную перерисовку. Кадры запрашиваются только при изменении сцены,
  камеры, выбора или размеров области.
- Скрытая или свёрнутая область графа не расходует CPU на физику и рендеринг.

### 13.4. Обязательные технические механизмы

1. **WebGL batching.** Узлы и рёбра рисуются пакетами; недопустим отдельный
   DOM/SVG-элемент на каждый узел или ребро.
2. **Layout в Worker.** Симуляция получает компактные typed arrays и
   передаёт обновления координат батчами. При расчёте разрешены зум, пан,
   фильтры и выбор.
3. **Сохранение layout.** Кэш содержит версию формата, область (`global` или
   `local:<идентификатор центральной страницы>`), стабильный ключ узла, `x`,
   `y` и `pinned`. Неизвестные и удалённые записи безопасно игнорируются.
4. **Детерминированность.** Начальная позиция нового узла и seed симуляции
   вычисляются из стабильного ключа и настроек. Одинаковые снимок, настройки
   и отсутствие кэша дают одинаковый итоговый layout.
5. **Агрегация.** Журналы можно автоматически сворачивать по месяцам или по
   годам; гранулярность выбирается настройкой, вложенные кластеры «год →
   месяц» не создаются. Цветовая группа с включённым «Сворачивать в кластер»
   представляется одним узлом со счётчиком. Каждый исходный узел входит
   максимум в один кластер: первое подошедшее правило с включённым
   сворачиванием имеет приоритет над временной агрегацией журналов. Кластер
   соединяется с внешними узлами агрегированными рёбрами; рёбра внутри
   кластера скрываются. Для автоматического режима при большом числе узлов
   порог сворачивания задаётся настройкой от 20 до 50 узлов на группу.
   Изменение фильтров пересчитывает состав и удаляет опустевшие кластеры.
   Желаемая развёрнутость сохраняется по стабильному ключу правила или
   периода; автоматическое упрощение может временно свернуть кластер, но не
   перезаписывает этот выбор и восстанавливает его при возврате запаса
   производительности.
6. **Ленивая отрисовка.** Подписи загружаются и рисуются по видимой области,
   зуму и приоритету; стрелки и эффекты отключаются раньше основных рёбер.
7. **Инкрементальное обновление.** После `graph-changed` frontend получает
   актуальный graph projection и сопоставляет его по стабильным ключам.
   Сохраняются координаты и фиксация оставшихся узлов; новые получают
   детерминированные позиции, удалённые исчезают. Камера и выбор не
   сбрасываются, если выбранный узел продолжает существовать.
8. **Автоматические упрощения.** По числу видимых элементов и измеренному
   frame time последовательно снижаются частота тиков физики, скрываются
   второстепенные подписи и стрелки, включается агрегация. При восстановлении
   запаса производительности автоматические упрощения не меняют ручные
   настройки пользователя.

## 14. Данные и IPC

В Rust добавляется чистый модуль проекции визуального графа, отдельный от
renderer. Он покрывается unit-тестами и не читает файлы поверх уже
построенного индекса.

Минимальные DTO (точные имена согласуются с существующими serde-типами):

```text
GraphNodeDto {
  id, title, kind, path, tags, degree,
  assetPath?, exists
}
GraphEdgeDto { id, source, target, weight }
GraphSnapshotDto { nodes, edges, revision }
GraphLayoutEntry { id, x, y, pinned }
```

Требуемые операции:

- получить снимок узлов и уникальных рёбер из текущего `Graph`;
- найти кратчайший путь по переданному видимому подграфу либо вернуть
  детерминированный путь из ядра;
- загрузить и атомарно сохранить layout;
- настройки `graphView` читаются и сохраняются существующими командами
  настроек.

Каждая новая IPC-команда регистрируется в `lib.rs` и получает типизированную
обёртку в `src/lib/api.ts`. Полный `Graph`, блоки и сырый markdown в визуальный
компонент не передаются.

Событие `graph-changed` остаётся сигналом обновления. Открытый глобальный или
локальный граф обновляется в реальном времени после собственных правок,
внешних изменений `.md` и синхронизации: новый снимок запрашивается сразу по
событию, без перезапуска вида и без ручного обновления. Допустимая задержка от
завершения переиндексации до отражения изменений на сцене — не более 5 секунд
при обычной нагрузке и не более 10 секунд на графе 10 000 узлов; частые события
коалесцируются внутри этого предела. Если событие пришло во время предыдущего
запроса, после его завершения запрашивается один актуальный снимок. Смена графа
загружает отдельные настройки, layout и камеру нового графа; данные предыдущего
графа не смешиваются с новыми.

## 15. Хранение состояния

- `.logtask/settings.json` → `graphView`: фильтры, цветовые группы, настройки
  отображения и физики, глубина локального графа, параметры агрегации.
- `.logtask/graph-layout.json`: только производные координаты и фиксация
  узлов, с версией схемы.
- `localStorage`: зум и позиция камеры, развёрнутость кластеров и последний
  выбранный режим панели, привязанные к идентификатору графа.

Повреждённый или устаревший layout не мешает открыть граф: записи читаются
частично, а непригодные игнорируются. Удаление layout возвращает
детерминированную первоначальную раскладку и не затрагивает страницы.

## 16. Тесты и проверка

### Автоматические проверки ядра

- Построение одного ребра при наличии прямой и обратной записи в индексе.
- Объединение повторных ссылок, противоположные ссылки, петли и степень узлов.
- Единый узел для одноимённых страницы и тега; виртуальные страницы.
- Включение/исключение журналов, вложений и несуществующих страниц.
- Кратчайший путь, отсутствие пути и детерминированный tie-break.
- Агрегация рёбер кластера без потери внешних связей.
- Round-trip существующего markdown не меняется: визуальный граф не пишет в
  `.md`.
- Чтение отсутствующего, частично повреждённого и устаревшего layout.

### Общие проверки проекта

```bash
cargo test --workspace
cargo fmt --check
cargo clippy --workspace -- -D warnings
npm run build
```

### Ручная и измеримая приёмка

- Пункт «Граф» открывает центральный вид; вид участвует в истории навигации.
- Видны все обычные страницы; журналы появляются только при включённой опции.
- Рёбра соответствуют `[[ссылкам]]` и тегам; обратные ссылки не дублируют их.
- Размер узла растёт с числом уникальных связей.
- Hover, первый и второй клики, сброс выбора и сообщение об отсутствии пути
  работают по разделу 7.
- Все фильтры, исключения и цветовые группы работают и сохраняются.
- Локальный граф показывает глубины 1–3 и переходит к глобальному графу.
- Зум, пан, перетаскивание, фиксация, контекстные меню и клавиатурное
  управление работают в обеих темах.
- Зум, камера, фильтры, группы, настройки и layout переживают перезапуск.
- На 1 000 узлов TTI ≤ 2 с; повторное открытие ≤ 300 мс.
- На 3 000 узлов пан/зум соответствуют бюджету FPS; в простое CPU не
  расходуется на постоянную симуляцию или перерисовку.
- На 5 000+ узлов каркас появляется < 1 с; на 10 000 узлов / 25 000 рёбер
  интерфейс не падает и соблюдает пределы блокировки, автоматически включая
  упрощения и агрегацию.
- Собственная правка, внешнее изменение `.md` и синхронизация обновляют
  открытый граф без ручного перезапуска: задержка после переиндексации ≤ 5 с
  при обычной нагрузке и ≤ 10 с на 10 000 узлов; только затронутая часть сцены
  меняется, координаты остальных узлов не сбрасываются.
