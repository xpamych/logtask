# Дизайн: системная тема, ресайз панелей, приветственный экран, палитра ppdb

Дата: 2026-10-01. Статус: утверждено пользователем (подход A, секции 1–2).

## Контекст

Logtask — Tauri 2 + SolidJS. Сейчас: тема только ручная (`theme: "dark"|"light"`
в `.logtask/settings.json`, применяется классом на `body`), колонки grid
захардкожены (`240px 1fr 320px` в `global.css`), при запуске без графа —
текстовая ошибка «граф не выбран», палитра близка к Logseq (Solarized-подобная
`#002b37` + акцент `#106ba3`).

## Требования (от пользователя)

1. Тема по умолчанию следует системе и переключается на лету при смене темы ОС.
2. Обе боковые панели ресайзятся перетаскиванием, ширина сохраняется.
3. При первом запуске (граф не выбран) — визуальный приветственный экран
   с понятным предложением выбрать папку графа. Недавних графов на нём нет
   (при чистой установке их не существует); переключение графов — отдельный
   сценарий через сайдбар, не через этот экран.
4. Цвета — не 1-в-1 Logseq; взять палитру сайта ppdb
   (`frontend-next/src/styles/design-tokens.css`).

## Решение (подход A — точечный, поверх текущего UI)

Бэкенд для темы не нужен: WebKitGTK поддерживает `prefers-color-scheme`.
Tauri-нативный детект темы и полный порт design-tokens отклонены (YAGNI).

### 1. Тема

- `settings.rs`: поле `theme` принимает `"system" | "light" | "dark"`;
  дефолт меняется на `"system"`. Старые значения `"dark"/"light"` из
  существующих settings.json продолжают работать (серверная миграция не нужна —
  строка как строка).
- `SettingsModal`: селект из трёх пунктов «Системная / Светлая / Тёмная».
- `App.tsx`: эффект вычисляет эффективную тему
  `settings.theme === "system" ? (matchMedia dark ? "dark" : "light") : settings.theme`
  и переключает классы `body.theme-dark/theme-light`. Подписка на
  `change` от `matchMedia("(prefers-color-scheme: dark)")` — пересчёт на лету
  (актуально только в режиме «Системная»; в ручных режимах подписка безвредна).

### 2. Палитра (global.css, только значения переменных)

Из `design-tokens.css` ppdb-site: primary `#09bec8` (бирюза), secondary
`#9b59b6` (фиолет), фоны `#222/#2a2a2a/#333`, текст `#fff/#b0b0b0/#888`,
границы `#3a3a3a`.

- Тёмная (`:root`): `--bg: #222222`, `--bg-alt: #2a2a2a`, `--bg-panel: #1a1a1a`,
  `--fg: #ffffff`, `--fg-muted: #b0b0b0`, `--accent: #09bec8`,
  `--accent-2: #9b59b6` (второй акцент — для тегов и вторичных элементов).
- Светлая (`body.theme-light`) — выведенная в том же духе: фон `#f4f6f7`,
  панели `#ffffff`, текст `#1c2733`, muted `#5c7080`, акцент затемнён до
  `#0891a0` для контраста на белом, `--accent-2: #7d3c98`.
- Цвета статусов по умолчанию (`settings.rs`, `default_statuses`) перекрашиваются
  в гармоничные с палитрой (success/warning/info/secondary из ppdb). Уже
  сохранённые пользовательские настройки не мигрируются.
- Все компоненты продолжают использовать переменные — правится только их
  определение; хардкоженных цветов в компонентах нет (проверить при
  реализации, заменить на переменные если найдутся).

### 3. Ресайз панелей

- `settings.rs`: новые поля `sidebarWidth: u32` (дефолт 240) и
  `taskpanelWidth: u32` (дефолт 320), serde camelCase (`sidebarWidth`,
  `taskpanelWidth`). Unit-тесты дефолтов — как у существующих полей.
- `App.tsx`: grid-колонки задаются инлайн-стилем
  `grid-template-columns: ${sidebarW()}px 1fr ${panelW()}px` (хардкод из CSS
  убирается); сигналы инициализируются из settings.
- Ручки: `<div class="panel-resizer">` (5px, `cursor: col-resize`, акцентная
  подсветка при hover/drag) между сайдбаром/центром и центром/панелью.
- Логика — маленький компонент `PanelResizer` (или хук `useResizer`):
  pointerdown → `setPointerCapture`, `user-select: none` на body;
  pointermove → новая ширина (левая — от левого края окна, правая — от
  правого), clamp 180–480px, запись в сигнал; pointerup → `settingsSave`
  с новыми ширинами.
- `src/lib/api.ts` и TS-тип `Settings` — новые поля.

### 4. Приветственный экран

- Новый компонент `src/components/Welcome.tsx`: по центру — иконка
  приложения, «Logtask», слоган «Журнал и задачи прямо над вашими
  .md-файлами в формате Logseq. Без базы данных — файлы остаются
  источником истины.», крупная акцентная кнопка «Выбрать папку графа».
- Показ: в `App.tsx` состояние «граф не выбран» (сейчас — `error()` от
  `graph_load` с текстом «граф не выбран…») рендерится как `<Welcome>`
  на всю ширину окна (сайдбар и правая панель скрываются). Различие
  «граф не выбран» vs другие ошибки — по тексту ошибки бэкенда
  (его достаточно, новых кодов не вводим).
- Кнопка: `pickGraphDir()` → выбран путь → существующий `openGraph(path)`
  → лента журналов; отмена диалога → остаёмся на приветствии.
- Недавних графов и гайдов на экране нет (решение пользователя).

### 5. Ошибки и краевые случаи

- `matchMedia` недоступен (старый WebKit) — fallback на dark.
- Ширины за пределами clamp при загрузке из settings — clamp при применении.
- Отмена диалога выбора графа — без ошибки, остаёмся на Welcome.
- Ошибка загрузки выбранного графа (неподходящая папка) — текст ошибки
  показывается на Welcome (не ломаем существующий `setError`).

### 6. Тестирование и документация

- Rust: unit-тесты serde-дефолтов новых полей settings (`theme` = "system",
  ширины 240/320) — по паттерну существующих тестов settings.rs.
- Фронт: `npx tsc --noEmit` + `npm run build` (тестов нет — как принято).
- Ручной прогон: смена темы ОС на лету; drag обеих ручек + перезапуск с
  сохранённой шириной; чистый запуск без `recent.json` → Welcome → выбор
  графа → лента; обе темы в новой палитре.
- `docs/03-ui.md` — обновить (тема, ресайзеры, Welcome, палитра) в том же
  коммите, по правилу AGENTS.md.

## YAGNI (сознательно не делаем)

- Нативный детект темы через Tauri API и события окна.
- Полный порт design-tokens (типографика/спейсинги/тени).
- Список недавних графов и мини-гайд на Welcome.
- Переключение/добавление графов с экрана Welcome.
- Миграция цветов статусов из существующих пользовательских settings.json.
