# Настройки как страница в центре — дизайн

Дата: 2026-10-05. Статус: утверждено пользователем (вариант «страница в
центре» + автосохранение; ревизия 2 — вход и переключение разделов через
левый сайдбар, без двухколоночного layout).

## Проблема

`SettingsModal` — одна длинная простыня: тема, шрифт, лимит канбана, день
недели, домашняя страница, рамка окна, редактор статусов, интеграции.
С появлением раздела «Интеграции» модалка стала перегруженной; нужна
группировка по разделам и больше места.

## Решение

Настройки становятся отдельным видом в центральной области (вместо модалки).
Вход и переключение разделов — через левую навигацию; сохранение —
автоматическое с индикатором-точкой.

## Навигация и архитектура

- Тип `View` в `src/App.tsx` расширяется вариантом
  `{ kind: "settings"; section: SettingsSection }`, где
  `SettingsSection = "general" | "appearance" | "tasks" | "integrations"`.
  Существующий boolean-сигнал `showSettings` заменяется на
  `settingsSection: Signal<SettingsSection | null>`:
  `currentView()` возвращает settings-вид, когда он не null (приоритет над
  остальными видами — настройки открываются явным действием);
  `applyView()` выставляет/сбрасывает его. Секция — часть `View`, поэтому
  переходы между разделами попадают в историю и ←/→/⌂/боковые кнопки мыши
  работают как с любым видом.
- В сайдбаре в секции «Навигация» под «Все страницы» добавляется пункт
  **«Настройки»**. Кнопка-шестерёнка убирается.
- Когда активен settings-вид, под пунктом «Настройки» появляются вложенные
  пункты с небольшим отступом (визуально — подразделы): **Общие**,
  **Внешний вид**, **Задачи**, **Интеграции**. Клик —
  `navigate({ kind: "settings", section })`. Активный раздел подсвечивается.
- Центральная область: в цепочке `<Show>` вид настроек проверяется первым
  (settings → page → tasks → pages → journal) и рендерит
  `SettingsPage` с активной секцией.
- Новый компонент `src/components/SettingsPage.tsx` заменяет
  `SettingsModal.tsx` (файл удаляется). Разделы — подкомпоненты в том же
  файле (`SectionGeneral`, `SectionAppearance`, `SectionTasks`);
  `IntegrationSources` встраивается как есть.
- Правая панель не меняется.
- Стили `.modal-*` в `global.css` сохраняются — их использует
  `QueryEditor.tsx`.

## Компоновка страницы

- Одна колонка: заголовок активного раздела + его контент (те же контролы,
  что сейчас в модалке, сгруппированные по разделам):
  - **Общие** — домашняя страница, первый день недели.
  - **Внешний вид** — тема, размер шрифта, системная рамка окна.
  - **Задачи** — лимит задач в колонке канбана, редактор статусов
    (цвет/видимость/название/порядок).
  - **Интеграции** — `IntegrationSources`.
- Никакого навигатора разделов внутри страницы — переключение только
  через сайдбар.

## Автосохранение и индикатор

- Любое изменение сразу обновляет `settings()` в App (тема и fontScale
  применяются мгновенно) и вызывает `settingsSave`:
  select/checkbox/color/перестановки статусов — немедленно;
  текстовые/number-поля и слайдер — с дебаунсом ~400 мс.
- Статус сохранения — сигнал в App: `"saved" | "dirty" | "error"`.
  `SettingsPage` получает колбэк `onSaveState` и поднимает состояние наверх;
  Sidebar показывает его точкой рядом с пунктом «Настройки»:
  - зелёная — всё сохранено (начальное состояние);
  - жёлтая — есть несохранённые изменения или идёт сохранение;
  - красная — ошибка сохранения (текст ошибки — в `title` точки и рядом
    с изменённым контролом/в шапке страницы).
- Ошибка сохранения не теряет состояние; следующее изменение повторяет
  попытку.
- Секреты интеграций сохраняются отдельно через `integrations_set_secret`
  (как сейчас) — не меняется; их состояние в точку не входит.

## Тестирование

Фронтенд-тестов в проекте нет — проверка типизацией (`npm run build`,
включает `tsc --noEmit`) и ручной прогон: вход по пункту «Настройки»,
вложенные разделы, автосохранение каждой группы полей, точка-индикатор,
←/→ по истории. Rust не затрагивается.
