# Настройки как страница в центре — дизайн

Дата: 2026-10-05. Статус: утверждено пользователем (вариант «страница в центре» + автосохранение).

## Проблема

`SettingsModal` — одна длинная простыня: тема, шрифт, лимит канбана, день
недели, домашняя страница, рамка окна, редактор статусов, интеграции.
С появлением раздела «Интеграции» модалка стала перегруженной; нужна
группировка по разделам и больше места.

## Решение

Настройки становятся отдельным видом в центральной области (вместо модалки)
с навигатором разделов слева и автосохранением.

## Навигация и архитектура

- Тип `View` в `src/App.tsx` расширяется вариантом `{ kind: "settings" }`.
  Существующий boolean-сигнал `showSettings` переиспользуется:
  `currentView()` возвращает `{ kind: "settings" }`, когда он true
  (приоритет над остальными видами — настройки открываются явным действием);
  `applyView()` выставляет `setShowSettings(v.kind === "settings")`.
  Настройки попадают в историю: ←/→/⌂ и боковые кнопки мыши работают
  как с любым видом.
- Шестерёнка в сайдбаре (`onOpenSettings`) делает
  `navigate({ kind: "settings" })`.
- Центральная область: в цепочке `<Show>` вид настроек проверяется первым
  (fallback-цепочка: settings → page → tasks → pages → journal).
- Новый компонент `src/components/SettingsPage.tsx` заменяет
  `SettingsModal.tsx` (файл удаляется). Разделы — подкомпоненты в том же
  файле (`SectionGeneral`, `SectionAppearance`, `SectionTasks`);
  `IntegrationSources` встраивается как есть.
- Правая панель не меняется (поведение как у видов «Задачи»/«Все страницы»:
  «Оглавление» просто показывает пустое/текущее состояние).
- Стили `.modal-*` в `global.css` сохраняются — их использует
  `QueryEditor.tsx`.

## Компоновка страницы

- Шапка: заголовок «Настройки», справа индикатор сохранения
  («Сохранение…» / «Сохранено» / текст ошибки красным).
- Двухколоночный layout: слева навигатор разделов (~180px, вертикальный
  список кнопок), справа контент активного раздела с собственным скроллом.
- Разделы:
  - **Общие** — домашняя страница, первый день недели.
  - **Внешний вид** — тема, размер шрифта, системная рамка окна.
  - **Задачи и канбан** — лимит задач в колонке, редактор статусов
    (цвет/видимость/название/порядок).
  - **Интеграции** — `IntegrationSources`.
- Адаптив: при ширине центра < ~560px навигатор превращается в
  горизонтальные табы над контентом (media query в `global.css`).

## Автосохранение

- Любое изменение сразу обновляет `settings()` в App (тема и fontScale
  применяются мгновенно) и вызывает `settingsSave`:
  select/checkbox/color/перестановки статусов — немедленно;
  текстовые/number-поля и слайдер — с дебаунсом ~400 мс
  (setTimeout + очистка, последний вызов побеждает).
- Статус сохранения — сигнал в `SettingsPage`: `idle | saving | saved |
  error`; индикатор в шапке. «Сохранено» гаснет через ~2 с.
- Ошибка сохранения показывается в шапке красным; состояние не теряется,
  следующее изменение повторяет сохранение.
- Секреты интеграций сохраняются отдельно через `integrations_set_secret`
  (как сейчас) — не меняется.

## Тестирование

Фронтенд-тестов в проекте нет — проверка типизацией (`npm run build`,
включает `tsc --noEmit`) и ручной прогон: открытие по шестерёнке,
переключение разделов, автосохранение каждой группы полей, ←/→ по истории,
адаптив на узком центре. Rust не затрагивается.
