# Редактирование виртуальных страниц

## Цель
Переход по ссылке на ещё не созданную страницу должен давать тот же инлайн-редактор первой записи, что и пустая существующая страница. После сохранения непустого текста файл `pages/<имя>.md` создаётся автоматически, новый блок появляется на странице, а связанные задачи и обратные ссылки сохраняются.

## Ограничения
- Пустой файл не создаётся при открытии виртуальной страницы, отмене редактирования или сохранении пустого текста.
- Сохраняются Logseq-совместимый формат, атомарная запись и защита от перезаписи внешних изменений.
- Новых IPC-команд и зависимостей не требуется.

## Подходы
- **Выбрано: создание внутри `block_create`.** Команда при отсутствии обычной страницы в индексе создаёт файл и добавляет первый блок одной операцией. Это исключает промежуточное состояние и лишний IPC.
- Два вызова `page_create` + `block_create` из SolidJS отклонены: между ними возможна гонка с внешним созданием или изменением файла.

## Изменения
- В `PageView` виртуальная страница использует существующий редактор пустой страницы; отдельная неинтерактивная подсказка удаляется.
- В Rust перед созданием проверяются допустимость имени и отсутствие конфликта с уже появившимся файлом; после записи выполняется обычная переиндексация и возврат UUID блока.
- Добавляется интеграционный тест создания первого блока на отсутствующей странице и защиты существующего файла. Обновляются `docs/03-ui.md` и при необходимости описание IPC.

## Проверка
`cargo test --workspace`, `cargo fmt --check`, `cargo clippy --workspace -- -D warnings`, `npm run build` и ручной сценарий: открыть виртуальную страницу → добавить запись → убедиться, что файл и блок созданы, обратные ссылки остались.
