# Дизайн оптимизации горячих функций визуального графа

Дата: 2026-11-04

## Назначение

Уменьшить время layout на больших графах без изменения внешнего вида,
алгоритма раскладки или функциональности.

## Замеры до изменения

- Индексация 706 файлов: 62,4 мс, узкого места нет.
- Rust проекция + BFS на 10 000 узлов / 25 000 рёбер: 151,9 мс.
- Frontend cold dev: 6,46 с, повторный: 1,98 с.
- `separateGraphNodes`: 55,4 мс за проход на 10 000 узлов.
- `applyHubGravity`: 27,3 мс за тик на 10 000 узлов.
- `componentTargetsForComponents`: 3,9 мс.

## Подход

Выбрано локальное ускорение примитивов без изменения алгоритма:

1. В `applyHubGravity` сохранить вычисление `Math.hypot`: сравнение квадратов
   расстояний меняет выбор hub на границах округления и отменено.
2. В `separateGraphNodes` убрать поиск индекса по Map для каждой пары.
   Фильтр по квадрату расстояния также отменён: на границе он меняет набор
   обрабатываемых коллизий. Точное расстояние вычисляется через `Math.hypot`.
3. Сохранить число итераций коллизий, силы, порядок узлов, порядок кадров,
   D3-физику, DTO и все визуальные настройки.

## Результаты

- `applyHubGravity`: исходный алгоритм сохранён, ускорения нет.
- `separateGraphNodes`: 55,4 мс → 52,5 мс в медиане серии; минимум 34,0 мс.
- Эталонные координаты hub и коллизий совпадают побайтово.
- Frontend suite: 125 тестов, production-сборка и audit успешны.
- Rust suite и clippy успешны.
- Визуальный smoke не выполнен из-за временной потери управления браузером.

Отклонён вариант уменьшения частоты коллизий: он может давать временные
пересечения узлов и менять анимацию.

## Проверки

- Существующие unit-тесты layout/geometry/renderEdges не меняются.
- Новый тест на идентичность позиций ближайших hub и разведения коллизий
  после оптимизации против эталонной реализации.
- Повторный микробенчмарк тех же 10 000 узлов до/после.
- Полный frontend suite, `npm run build`, `npm audit --omit=dev`.
- Полный Rust suite и clippy для контроля смежных модулей.
- Визуальный smoke-бенчмарк на 10 000 узлов: граф остаётся тем же по смыслу,
  узлы не пересекаются, выбор/зум/подписи работают.

## Коммит

Отдельный коммит с результатами замеров до/после. GitHub workflows добавляются
отдельным коммитом и не смешиваются с оптимизацией.
