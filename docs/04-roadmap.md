# План реализации

Чек-лист по фазам. Каждая фаза самодостаточна — после неё приложение можно
запускать и пользоваться. Все пункты ниже при старте фазы заводятся как
задачи в самом Logtask (dogfooding).

## Фаза 0 — Скелет (1–2 дня)
- [ ] создать репозиторий `git init`, структуру: `src-tauri/`, `src/`,
  `docs/`, `.gitignore`
- [ ] `cargo create-tauri-app` (шаблон SolidJS+TS), проверить сборку и запуск
      на Linux (webkit2gtk4.1 уже есть)
- [ ] крейт `logtask-core` внутри репо (workspace), пустой + 1 unit-тест
- [ ] CI-примитивы локально: `cargo fmt`, `clippy -D warnings`, `tsc --noEmit`,
      `npm run lint` (solid)

**Критерий готовности**: `cargo tauri dev` открывает пустое окно <500 мс.

## Фаза 1 — Парсер и ядро (3–5 дней)
- [ ] `parser.rs`: bullet-outliner (отступы tab/2+ пробелов), вложенности,
      `:LOGBOOK:` + CLOCK, свойства `key:: value`, маркеры и приоритеты
- [ ] `model.rs`: Page/Block/Task/Link из 01-architecture
- [ ] `index.rs`: построение индекса,反向 ссылки (backlinks), теги, поиск
- [ ] `query.rs`: фильтры + сортировки для канбона/матрицы/запросов
- [ ] тесты-фикстуры: 3 реальных файла из твоего графа
      (`journals/2026_09_11.md`, `pages/PPDB - TODO.md`, `pages/Arch Linux.md`)
- [ ] бенчмарк: индекс твоего графа (700 файлов) — уложиться <100 мс

**Критерий**: `cargo test` зелёный, граф парсится без потерь (round-trip:
прочитать → сериализовать → байты совпадают).

## Фаза 2 — Чтение: лента журнала + страницы (3–4 дня)
- [ ] IPC `graph_load`, `journal_day`, `journal_prev`, `page_get`, `backlinks_get`
- [ ] UI: лента дней с виртуальным скроллом, рендер блоков
- [ ] UI: кликабельные `[[ссылки]]`, `#теги`, открытие страниц
- [ ] UI: секция «Ссылки» (обратные ссылки) внизу страницы
- [ ] UI: сайдбар (избранное, дерево страниц, поиск, мини-календарь)
- [ ] `notify` watcher: внешний `touch` файла обновляет UI

**Критерий**: можно листать журнал, открывать страницы, видеть обратные ссылки.

## Фаза 3 — Кастомный список задач (3–4 дня)
- [ ] IPC `query_run`, формат `filter`/`sort` (JSON)
- [ ] UI вкладки: **Канбан** — колонки статусов, drag&drop, карточки
- [ ] UI: **Мои запросы** — простые списки по queries из settings
- [ ] импорт `:default-queries` из `logseq/config.edn` (Сейчас/Работа/PPDB/
      Gitea/Остальные дела) → saved-запросы
- [ ] фильтры канбона (статус/тег/страница/дата), состояние запоминается
- [ ] клик по карточке → переход к блоку в ленте с подсветкой

**Критерий**: твои текущие группы задач работают в новой панели, drag&drop
меняет статус в .md.

## Фаза 4 — Матрица Эйзенхауэра (2–3 дня)
- [ ] UI вкладка **Матрица**: 4 квадранта, drag&drop между клетками
- [ ] чтение/запись `urgency::` / `importance::`, маппинг приоритетов
      ([#A]/[#B]/[#C] → важность)
- [ ] автосрочность: deadline в пределах N дней → urgency high в вычислениях
- [ ] индикатор на блоках в ленте (цвет/размер), меню по `mod+enter`
- [ ] цвет карточек по приоритету, лимит видимых + разворот

**Критерий**: задача перетаскивается в «Сделать» → в .md обновляются
свойства и Logseq показывает её там же.

## Фаза 5 — Редактирование и запись (4–6 дней)
- [ ] contenteditable для блоков: создание/удаление/вкладывание
- [ ] редактирование текста: `[[`-автодополнение страниц и тегов
- [ ] меню быстрого редактирования: статус, приоритет, срочность, важность,
      deadline/scheduled
- [ ] запись: атомарный rename + fsync, только затронутых строк
- [ ] CLOCK: запуск/остановка трекинга на задаче, логика `:LOGBOOK:`
- [ ] конфликты: mtime-проверка перед записью, merge по блокам
- [ ] создание сегодняшней страницы при первом запуске дня

**Критерий**: дневник ведёшь в Logtask как раньше в Logseq, часы считаются,
конфликтов с Syncthing нет.

## Фаза 6 — Настройки, темы, полировка (2–4 дня)
- [ ] настройки: статусы (набор/цвета/порядок/шорткаты), первая неделя,
      тема свет/тема, размер шрифтов
- [ ] настройки queries прямо из UI (add/remove/edit)
- [ ] все шорткаты из 03-ui + переназначение
- [ ] tray, «открыть граф», меню "_recent graphs"
- [ ] наблюдение: лог медленных IPC + тест на «нет фризов»
- [ ] сборка релиза (AppImage/rpm для Linux), размер <15 МБ

**Критерий**: сборка разворачивается на твоей машине, настройки
сохраняются между запусками.

## Фаза 7 — Долгий ящик (по запросу)
- [ ] кэш индекса на диск (графы от 10 000 файлов)
- [ ] мобильный вид / web
- [ ] экспорт (HTML/share), печать
- [ ] block refs `((uuid))` — создание
- [ ] lua-подобные макросы без системы плагинов (просто repl)
- [ ] управление активными часами (clock out / resume)

## Риски и решения
- **webkit2gtk-версии** — обновления Linux могут ломать ABI; фиксируем
  совместимую версию в `src-tauri/tauri.conf.json` + AppImage для изоляции
- **Range-редактирование в contenteditable** — брать наработки Logseq
  (их `:editor/...`-обработки) и упрощённый contenteditable-плагин, не
  CodeMirror
- **inotify на больших графах** — оценка после фазы 1: watch рекурсивно
  по дереву, но не по индивидуальным файлам
- **Имена файлов с кириллицей/пробелами** — покрыты тестами фазы 1 (фикстуры)
